## 架构速览(当前实现)

```
rutis-dsh up → Rust 进程(TCP listener + LlmSeam + aimux)
                └─ spawn 官方 dsh(node, stdio 归它)
                     └─ profile 组合(dsh-base + 形态 bundle + rutis-bridge 层)
                          └─ rutis-bridge 插件:
                             · settings `llm-aimux: providers.<route>` → 路由集(热增删)
                             · registerConfigurableProviders(页面可见)+ registerAdapter
                             · stream/listModels 过线;apiKeyEnv 凭据 per-request 解析随调用过线
```

- 协议:行帧 JSON over loopback TCP(`rutis-cordis::tcp`),fd3 留 Linux lane
- Rust 侧 llm 缝:`llm/stream`(chunk 以 `llm/chunk` ntf 流回,dispatchId 关联,finish 走 res)+ `llm/listModels`(aimux 真拉 /models,带缓存);per-(provider,key,model) 构造缓存 provider
- 事件缝 v1:插件声明 `forwardEvents` → `evt/emit` ntf 回流 Rust stderr 日志
- 断连语义(§十.4):桥死不杀 dsh(TS 侧挂了 socket error 处理,后续调用报 `bridgeDisconnected` LlmError);runner 以桥断连为权威退出信号

## 已解决的坑(新机可能复遇)

| 坑 | 解 |
|---|---|
| npm 官方源极慢/卡死 | npmmirror + pnpm(见上);macOS 直连官方源无碍 |
| tarball 装插件后组合层不出现 | ① package.json exports 必须导出 `./cordis.patch.yml` ② 装完必须在 profile 目录补 `pnpm install` 物化链接 |
| **同版本 tarball 重装不更新内容** | pnpm 对同路径同版本的 `file:` tarball 视为已满足("added 0");必须 `dsh plugin --profile X remove rutis-bridge` 再 add,并用 `grep backendFor node_modules/rutis-bridge/lib/plugin.js` 之类确认新代码真的落了 |
| **路由名与官方 pi-ai provider 同名** | `deepseek` 等名被官方声明,DUPLICATE_DIRECTORY 崩宿主;路由名换任意标签 + profile `provider: <aimux 名>`(349fa1c);注册面已 fail-soft |
| **node <23.8 起不来** | 官方 `session-persistence-jsonl` 要 `node:zlib createZstdDecompress`;macOS 用 nvm 装 24,跑 runner 时 `PATH="$HOME/.nvm/versions/node/v24.x/bin:$PATH"`(dsh bin 的 shebang `env node` 也吃 PATH) |
| Windows spawn 找不到 dsh | npm 全局命令是 .cmd shim;runner 已做 cmd /c fallback;或 `RUTIS_DSH_BIN="node.exe <bin.js 绝对路径>"`(支持空格多段) |
| 构建中 proc-macro DLL 消失(E0463) | SAC/Defender 删产物;关 SAC 或排除 target;`cargo clean` 全量重建可救(Windows) |
| 测试二进制 os 4551 | SAC 拦新 exe;touch 源码重编新 hash 通常绕过;根治靠关 SAC(Windows) |
| `llm/` 调用 dsh 侧显示 `UNKNOWN: ...` | 桥错误已统一 LlmError(带 code);若再见,查 bridge.ts settle 路径 |
| headless 单轮 LLM 失败后进程不退 | ✓已修(`aa1e274`):空闲 unref + 在飞 hold/release;见 §下一步 5 |
| **订阅 dispatch 语义事件会掐死 turn** | waterfall/serial 事件(如 `agent/request`、`agent/pre-step`)绝不进 forwardEvents——cordis waterfall 是 next() 链,被动监听者不调 next() 即否决全链;只收证实纯 emit 的事件(`12c6e0a` 教训) |
