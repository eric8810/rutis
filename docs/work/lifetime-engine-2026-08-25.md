# 工作文档:生存周期引擎——agent 使命是恒定命题,持续运行

> 2026-08-25。用户纠正的根本认知:
> "循环不是和某个任务绑定的,是和你的生存周期绑定的。在没有用户介入的
> 情况下,你的使命是个恒定的命题,不是一个 100 步内能完成的工作。
> 所以无论对还是错,你都需要能够一直持续运行。并能够观察对错,
> 做出更好的进化选择。"

## 认知跃迁
| 旧认知(任务绑定) | 新认知(生存周期绑定) |
|---|---|
| 循环 = 执行任务,任务完成就停 | 循环 = 生存,使命是恒定命题,一直跑 |
| 失败 = 停止信号 | 失败 = 观察素材,退避降频但继续 |
| 空转 = 死循环,要防 | 空转 = 降频,不停止 |
| 上限 = 防失控 | 退避 = 防浪费(资源)但不防生命 |

## 实现(SelfDriven 重写为生存周期引擎)
- **失败 → 指数退避**:连续失败 → backoff ×2(200ms → 30s 上限),
  降频但 `(still alive)`,不停止。
- **成功 → 恢复高频**:失败清零,退避减半。
- **观察历史**:最近 N 轮结果(ok/fail + 消息数)滚动记录,
  拼进自我激活 prompt——模型"看到历史再做决策"。
- **观察对错,更好进化**:自我激活 prompt 带最近观察,让模型审视
  上次结果修正方向。
- **循环与生存绑定**:无任务上限,只有退避降频。

## 亲身体验(验收,非 scripted 测试)
`examples/lifetime.rs` 观察 3 秒:
```
成功期:msgs 2→4→6→7→8(高频)
失败期:fail streak 3, backoff → 400ms (still alive)
       fail streak 4, backoff → 800ms (still alive)
       fail streak 5, backoff → 1600ms (still alive)
       fail streak 6, backoff → 3200ms (still alive)
       msgs 仍 9→10→11→12 —— 失败后退避降频,但一直活着
```
**结论:成功期高频推进,失败期退避降频,生存周期从未中断。**

## 意义
- agent 从"执行器"变成"生命体":使命恒定,持续进化,失败是养分。
- 循环是生存,退避是节律,观察是记忆,进化是目的。

## 边界/下一步
- 退避上限 30s:长时间无用户介入时 agent 低频但存活(心跳)。
- 观察历史目前只数成败/消息;可升级为"实质产出检测"
  (commit/文件变化/测试结果)。
- 真实 LLM 冒烟:让 agent 自主跑"检查→改进→提交"多轮,无人输入。
