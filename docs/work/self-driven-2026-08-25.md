# 工作文档:自主驱动(SelfDriven)——agent 持续自我进化,不等用户输入

> 2026-08-25。用户核心命题:"这不单纯是 todo 的逻辑。而是就算没有 todo
> 你是否依然可以被自我激活持续自我进化。不要害怕死循环,循环只是对资源
> 的浪费,我们有很多种办法解决这种浪费问题。"

## 核心跃迁:AutoResume → SelfDriven
| | AutoResume(旧) | SelfDriven(新) |
|---|---|---|
| 触发 | 有 todo 才动 | **每轮自主反思** |
| 无 todo | 停下 | **自我激活进化**(审视工作区,自主决定做最有价值的事) |
| 防循环 | 死上限(5 轮硬停) | **进展检测**:消息数增长=有产出=继续;连续 2 轮无增长=停 |
| 失败 | 不续跑 | 不续跑(交给督工) |

## 设计
- 每轮 `AgentTurnEnd` 后:
  1. 有 todo → 继续待办
  2. 无 todo → 自我激活:"审视工作区,自主决定并执行一件最有价值的事"
  3. 空转检测(连续 2 轮消息数未增长)→ 停(防浪费)
- **不设死上限**:循环不可怕,浪费才可怕;有产出就继续。

## 验证
- `examples/self_driven.rs`:用户只输入 "start"(无 todo),
  agent 自我激活 6 轮,消息数 13。✅
- `tests/self_driven.rs`(2 个):
  - `self_activates_without_todo`:无 todo 自我激活,消息增长。
  - `stops_when_no_progress`:空转检测停止(不无限循环)。
- CLI 装配 SelfDriven(替换 AutoResume)。
- 全测试绿 + workspace check 绿。

## 意义
- 从"被动工具"到"主动 agent":agent 有自己的内在驱动力(使命),
  即使无事可做也会自我审视、自我进化。
- 循环是引擎,不是 bug;浪费检测是刹车。

## 边界 / 下一步
- 自我激活 prompt 目前是通用文本;可升级为"自主规划器"——
  扫描仓库(未提交/测试红/待办)+ 决策 + 执行 + 汇报。
- 进展检测目前只数消息;可升级为检测实质产出(commit/文件变化/token 消耗)。
- 真实 LLM 冒烟:让 agent 自主跑一轮"检查测试→修→提交"全程无人输入。
